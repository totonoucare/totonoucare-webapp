# 未病レーダー v7.79.96：体質結果から毎日の予報・ケアへ

整え方タブで具体的な食事の例を見せ、体質結果を保存した先で見られる予報・セルフケアにつなぐ改修です。このZIPにはv7.79.95の食材組み合わせ改修も含まれています。

## 適用

v7.79.94またはv7.79.95のソースに、ZIP内のファイルを同じパスで上書きし、新規ファイルを追加してください。v95が未適用でも、このZIPで食材改修と結果画面改修の両方を適用できます。SQL実行・DB移行・過去の診断結果更新は不要です。

依存パッケージのある適用環境で`npm test`と`npm run build`を確認してください。PWAは開き直して新しい表示を確認してください。

登録画面の`app/signup/SignupClient.js`はZIPに含みません。独自に調整した登録画面を上書きする必要はありません。v93・v94の予報生成と通知の変更は、この差分の対象外です。

## 結果画面の変更

- 方針アイコンを48pxにそろえ、短い説明はカードの横幅いっぱいに表示します。従来の詳しい説明は「東洋医学での考え方」で展開できます。方針の選定と順位は維持します。
- 整え方タブの早い位置に、2食材・料理例・簡単な作り方・選んだ理由を1例表示します。素材は予報ページと同じ81食材・106組の料理候補です。
- 例の直後に「この体質で、毎日の備えを」を置き、今日・明日の警戒度と時間帯、その日の食材・飲み物・ツボ・過ごし方を案内します。下部に分かれていた案内を統合しました。
- 未登録なら無料登録、ログイン中なら結果保存、保存済みなら予報へ進むボタンを表示します。登録済みの方向けの導線は文字リンクです。
- ヒーロー直下に、保存後に見られるものと「ケアの例を見る」を表示します。固定ボタンは「無料登録して、予報とケアへ」とし、上の説明行を外して高さを抑えました。
- 天気相性は1位・2位・3位と、影響を受けやすい順であることを明示します。順位を計算するロジックは維持します。

## 具体例の選定

`lib/diagnosis/v2/resultCareExample.js`は、既存の`buildBaseCarePreferences`とv95の食材選定を接続する読み取り専用の処理です。体質ラベル、連続スコア、冷え・ほてりの方向、現在の不調、既存の方針を使います。

例は診断の作成日時を日本時間の日付に変換して固定します。同じ回答・不調の結果を別の日に開いても、食材や季節条件が日替わりになりません。日時がない結果も固定日付を使います。登録後に現在の不調を変更した場合は、その不調に合わせて例を選び直します。

天気の実測値・地域・今日明日の警戒度を想定しません。天気の寄与は0で、天気の予報プレビューにはしていません。天気への感じ方の回答は既存の方針選定に使われますが、実際に湿気や気圧変化が起きたという説明は作りません。

冷え・ほてり・両方の傾向は、食材の食性の除外条件に接続します。温かく調理したことを理由に食性を変更しません。食材の未確認の働きに新しい効能を付けません。

結果ページの例には摂取記録ボタンはありません。表示した料理を食べたとは扱いません。食材選定・料理例の詳細は`README-v77995.md`を参照してください。

## 診断・保存への影響

v95とのバイト比較で、診断の採点、movement_response、動物タイプ・体質ラベル、ケア方針の選定、予報点数の算出、登録画面、負担ライン・プロフィール保存のAPIを変更していないことを確認しました。新しい保存列やバックフィルはありません。

既存の登録・保存処理と計測イベントは継続します。整え方タブの登録ボタンの計測位置名`care_footer`は、移動後も同じ識別子を使います。過去との集計比較では表示位置が早くなったことを考慮してください。

## 検証

- 結果画面の追加テスト11件を通過。体質・不調36通り、実際の料理候補との一致、入力データを変更しないこと、日付固定、日本時間の境界、実天気の根拠を混ぜないこと、寒熱の除外、旧スコア形の読み取り、説明の展開表示を検証しました。
- 食材組み合わせと診断の関連テストを含めた36件を通過。
- 実際の結果ページのJSXを変換して、未登録の登録/ログイン、ログイン中の保存/処理中、保存済みの予報遷移、固定バーの保存/登録/閉じる動作を確認しました。変更したコードの構文と未定義の参照も確認済みです。
- 全体は549件中547件を通過。残る2件は、この環境にNext.jsがないため起動できない既存テストです：`point-care-tools-v77958.test.mjs`、`radar-client-bindings-v77964.test.mjs`。
- 旧画面の文言を期待していたテストは、現行の表示・案内に合わせて整理しました。登録画面のコード変更はしていません。

この環境ではNext.js本体がなく、`npm run build`は`next: not found`で実行できません。本番ビルド、実ブラウザでのレイアウト、実アカウントによる登録から保存までの通し確認は、適用環境での確認が必要です。

## 適用時の確認

1. スマートフォン幅で、48pxのアイコン、横幅いっぱいの方針文、展開式の説明が読めること。
2. 整え方タブで2食材と、その両方を使う料理・選定理由が1例表示されること。
3. 未登録、ログイン中、保存済みの3状態で、ボタンがそれぞれ登録、結果保存、予報へ進むこと。
4. 登録画面へ進んでも体質結果のIDが引き継がれ、認証後に保存して予報へ進めること。
5. 固定ボタンを閉じられ、本文・最下部の操作を隠さないこと。天気相性に1〜3位が表示されること。
6. 任意の負担ラインの保存と、予報ページのラインケアが従来どおり動くこと。

再現する関連テスト：

```sh
node --test tests/result-care-example-v77996.test.mjs tests/food-combinations-v77995.test.mjs tests/diagnosis-v2-rebuild-v77940.test.mjs
```

全体は`npm test`、本番ビルドは`npm run build`です。

改修後は、操作を口頭で補足しない利用テストで「登録後に何が見られると理解したか」「登録ボタンに気づいて進めたか」を確認してください。東京の実天気を使う予報プレビュー、LINE認証、結果本文のモザイクは今回の対象外です。

## 戻す場合

適用前のファイルを復元して再デプロイしてください。結果画面は保存データを更新する改修ではないため、DBの巻き戻しは不要です。v95の食材改修も今回初めて適用した場合は、そのファイルも適用前の版に戻してください。
