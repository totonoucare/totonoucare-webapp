# 未病レーダー v7.79.95：食べるケアの組み合わせ対応

体質に合う食材を土台に、気象負担の強さに応じて天気への備えを加え、2食材の組み合わせ・料理例・選んだ理由を表示する差分です。

## 適用

v7.79.92〜v7.79.94系列のソースへ、ZIP内のファイルを同じパスに上書きしてください。新規ファイルもすべて追加してください。SQL実行・DB移行・過去データ更新は不要です。適用後は依存パッケージのある開発環境で `npm run build` を確認してデプロイし、PWAを開き直してください。

この差分は食べるケアの変更です。体質チェック・movement_response・動物タイプ・体質ラベル・予報点数の算出を変更しません。登録画面を変更するファイルは含めていません。v94の通知変更も上書きしません。

## 表示と記録

- 主候補1組＋代替候補2組。各組は2食材で、その両方を使う料理例と簡単な調理方法を表示します。
- 明日の食事は翌日の食事全般の提案です。飲み物の翌朝提案と、今夜の任意の補食は従来どおり区別します。
- 「食べた」は食材ごとに記録します。片方の記録から、組み合わせ全体の摂取・料理の完食・量・効果を推定しません。
- 翌日の食事提案は `next_day`、従来の翌朝飲食は `breakfast`。どちらも事前に「食べた／飲んだ」を保存できないようAPIで制限します。
- 食材のIDと摂取記録のcanonical keyを維持します。組み合わせのIDは料理型と2食材から安定生成し、記録の識別には使いません。
- 既存の診断・保存予報・保存済みの記録スナップショットを更新しません。予報画面で再構成される食べるケアから新表示になります。

## 選定設計

81食材の登録内容と14飲料を維持し、料理として成立する106組の候補を追加しました。81食材すべてに組み合わせ候補があります。

伝統的な働きが未確認の食材に効能を追加することは避け、確認済みの食材と組ませる料理上の相方として扱います。調理温度によって食材の食性を変更しません。相反する食性は候補段階で除外します。

体質・不調・天気・ケア方針の根拠を別々に保持します。同じ働きへの一致でも、最大の根拠だけで他を消す処理を使いません。各区分内の寄与は主項目＋補助項目の範囲に制限します。

天気の設計上の重みは、個人向け予報のsignalに応じて1.0／2.5／4.2。体質は主ラベル3.2・副ラベル2.6を基準に、利用可能な連続スコアで調整します。これらは製品の選定用の設計値です。臨床効果や最適係数の検証結果を表す値ではありません。

寒さ・暑さでは登録済みの食性も根拠に使い、料理の温かさと区別して保存します。薬味・調味料は少量使いを想定し、主食材と同じ寄与を与えません。気圧変化・寒暖差は実際に選ばれたケア方針を通じて食材に結び付け、食材が気圧を治療するという説明を作りません。

気象負担がある日は天気に合う根拠を持つ候補を優先し、強い日はさらにその適合性を重視します。適合度が近い候補の範囲で日付によるローテーションを行います。実際の摂取記録にある直近3日の食材は、新しい適合候補が残る範囲で回避します。表示しただけの食材を食べたとは扱いません。
