# v7.79.10 暮らすケアの文脈優先化

## 修正した違和感

v7.79.9では、暮らすカードの上段に`まずはこれ`と主提案の見出しを出し、その直後に`今日の一手`として同じ内容を再表示していた。場面より先に操作だけが見えるため、取っ手などの具体策が脈絡なく始まって見えた。

また、身体操作と環境実験を日付で強制交代していたため、今日の天気・選択中の不調への適合度より、表示の多様性が優先される場合があった。身体操作レーン内でも、四場面を確保するために最高点から離れた候補まで主役候補へ入れていた。

## UI契約

- 暮らすカードは`今日の一手`または`今夜の一手`から直接始める
- `まずはこれ`の上段ブロックを置かない
- `ケア種別 → 具体的な使用場面 → 実際の一手 → 理由 → できた目安`の順で表示
- 身体操作の場面は`持つ・運ぶ時は`のような一般分類だけにしない
- 商品名・ショップ検索語は引き続き対策ケアへ出さない

## 選定契約

### レーン間

1. 身体操作と環境実験の最高適合点を比較する
2. 点差が`0.75`を超える時は、高い側を主提案に固定する
3. 点差が`0.75`以内の時だけ、同じ条件の中で日付ローテーションする
4. 基礎ケアは主提案にせず、強い天気ストレスまたは余力が小さい日の補助案に限る

### レーン内

1. 選択中の不調に対応する候補を優先する
2. 最高点との差が`0.75`以内の場面だけを主提案のローテーション対象にする
3. 同じ場面の具体策も、最高点との差が`0.75`以内だけを回す
4. 候補数を増やす目的で、低適合候補を主提案へ補充しない

### 身体操作の適用範囲

身体操作の不調タグは、操作との直接的なつながりが説明できる範囲へ絞る。選択中の不調に該当候補がない場合は、身体操作レーンを無理に有効化せず、天気に合う環境実験から提案する。

これは身体操作を弱める変更ではない。関連がある日に限って独自の身体操作を主役へ出し、関係の薄い日に唐突な操作が出ることを防ぐ変更である。

## 表示・検証用データ

`selection_basis`へ次を返す。

- `primary_kind`
- `body_score`
- `environment_score`
- `primary_candidate_score`
- `lane_score_gap`
- `near_tie_delta`
- `lane_rotation_applied`
- `foundation_included`

## 変更しないもの

- 体調ゆらぎ度
- 天気ストレス
- 体質親和性
- 余力補正
- 出やすいサイン
- 食べるケア
- ほぐすケア
- 予報保存形式
- DB / SQL / environment variables
