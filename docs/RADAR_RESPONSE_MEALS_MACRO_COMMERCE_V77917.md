# v7.79.17 身体反応起点の食べるケア・継続商品の接続

## 目的

食べるケアを、天気に対応する無難な食事の反復から、今日の身体反応に合う具体的な食事選択へ変える。同時に、ミクロな一食とマクロな商品購入を分離し、ショップでは数日から数週間続ける意味がある商品を提案する。

## 選定モデル

献立は次の順で選ぶ。

1. 共通反応プロファイルから7つの方針、反応方向、余力、気血水、選択中の不調を受け取る。
2. `食事を軽くしすぎて余力を減らす`、`油・甘味・冷たい物が重なって食後の重さを残す`など、今日の食べ方で起こりやすい崩れを短く示す。
3. 方針・不調・体質への適合度で、監修済みの完成料理を採点する。
4. 天気は温かさ、汁気、軽さなどの調理適合度へ小さく加点する。天気名だけで料理を決めない。
5. 適合上位の中で料理文化、主なたんぱく源、料理形式をずらし、同じ見た目と味の反復を抑える。

## 場面別カタログ

| カタログ | 件数 | 画面上の役割 |
| --- | ---: | --- |
| 今日の完成料理 | 56 | 自炊・家庭の一食として成立する具体案 |
| 買って済ませる | 28 | 具や味を含むコンビニ・惣菜等の買い合わせ |
| 外で選ぶ | 21 | 店で注文できる料理と量・副菜等の選び方 |
| 明日の朝食 | 35 | 朝食として成立し、今夜の準備も書ける案 |
| 今夜の空腹時 | 21 | 空腹でなければ食べない任意の軽食 |

料理名は部品の自由合成ではなく、自然な一皿または組み合わせを一件ずつ定義する。`おにぎり`、`パン`、`スープ`だけのように購入時の判断が残る一般名一語は使わない。

## 今日と明日の役割

### 今日

- 今日の一食
- 今日は重ねない
- 買って済ませるなら
- 外で選ぶなら
- 別の気分なら
- 飲み物を合わせるなら（既存候補がある場合）

### 明日

- 明日の朝の一食
- 今夜、小腹が空いたら
- 今夜〜明朝に重ねない
- 今夜しておくこと
- 朝の別案
- 飲み物を合わせるなら（既存候補がある場合）

todayとtomorrowは別カタログを使う。完成夕食を明朝の提案へ流用せず、夜食は空腹時だけ、準備は朝の判断を減らす一手として書く。

## ローテーション

- 同じ日・同じ条件では同じ候補を返す。
- 適合上位候補を対象日の序数と安定ハッシュで巡回する。
- 料理文化、主たんぱく源、形式が異なる候補を別案で優先する。
- 今日と明日の主献立は別カタログなので同じ料理にならない。
- 同じ条件が続いても、隣接日に同じ主献立を出さず、6日間で3種類以上を出す。

## ショップとの時間軸分離

今日の料理名や材料はショップへ渡さない。`buildFoodCommerceContext`が体質・不調・反応方向・余力から次の継続軸を作る。

| 軸 | 例 | 用途 |
| --- | --- | --- |
| 7つの方針 | ささえる、ながす、うるおす | 商品棚全体の優先順位 |
| 食養生機能 | 健脾、補気、理気、化湿、利水、温中など | 茶・素材・常備食の検索意図 |
| 栄養上の継続課題 | 食事を抜かない、たんぱく質、鉄・B群、食物繊維・ミネラル、カフェイン移行など | 続ける理由と商品形式 |
| 商品の役割 | 日常茶、常備食、調理済み食、宅食、栄養補助 | 購入可能な単位への変換 |

単日の天気はこの継続軸に含めない。ショップ側では必要に応じて季節や予報を軽い順位調整にだけ使える。栄養補助は、余力小・気虚・血虚・疲れ・めまいなどの継続理由がある場合に限る。

## 変更していないもの

- 予報点数とシグナル
- 天気ストレス計算
- 出やすいサイン
- 暮らすケアとほぐすケア
- 暮らすケアの商品境界
- DBスキーマと環境変数

## 回帰条件

- 7天気 × 9不調 × 4体質の252条件で、今日と明日の主献立を一致させない。
- 類似条件6日間で隣接日の主献立を重複させず、3種類以上を提示する。
- 購入案は具・味・組み合わせまで書く。
- 同じ天気でも身体反応と不調が異なれば、反応ラベルと主献立を変える。
- ショップ用プロファイルは、料理ID・料理名・単日の天気で変えない。
- 予報からショップへは継続ケア軸だけを渡す。
