# v7.79.15 暮らすケアと商品導線の境界整理

## 目的

暮らすケアの身体操作を商品販売の都合で歪めず、環境調整の商品だけを予想される身体反応へ正確につなぐ。同時に、身体操作文の不自然な物品限定を取り除き、独自の身体操作OSを一般生活語で再現する。

## 身体の使い方

身体操作は、ユーザーがその場で試して動きの軽さを確認するケアとして完結させる。22候補はすべて`shop_eligible=false / item_role=null`とし、`tension-*` action idをショップ検索語へ変換しない。

持ち方の正本は次の順序とする。

1. 指先を物へ添えた接触位置は残す。
2. 手首に近い手のひらの付け根を物へ近づける。
3. 手のひら中央に浅いくぼみを残し、物を包む。
4. 親指だけで握り込まず、小指側から包み、親指は軽く添える。

これは特定の細い持ち手や取っ手がある物だけの操作ではない。物の形、持ち手、個数、家事を根拠なく限定しない。条件が必要な文は`近づける物なら`、`荷物を分けられる時は`のように条件付きで示す。

## 環境調整

環境調整は、天気そのものではなく、予想される身体反応と生活上の増幅場面を人間工学・回復環境で受け止める。

現行候補は次の11件。

- 腕の重さを預ける
- 画面・読み物の高さを上げる
- 荷物の重さを分ける
- 作業の高さと距離を寄せる
- 足裏を支持する
- 光刺激を絞る
- 背中と腰を支持する
- 脚を面で支持する
- 横向き寝具でねじれを減らす
- 見る物を正面へ集める
- 音刺激を減らす

`高温 → 遮熱用品`、`高温 → 冷房風向き`、`湿気 → 寝具除湿`へ直接つなぐ3候補は、個別ケア候補から削除した。暑熱・寒冷などの一般的な安全対策は予報側の注意表示で扱い、一般ショップ方針に残る気候用品と個別ケアの選定を混同しない。

## ショップ接続

`lifestyle_plan`は表示カードとは別に`shop_context`を返す。

- `action_id`
- `item_role`
- `scene_family`
- `care_needs`
- `target_response`
- `symptom_key`
- `selected_because`

画面に環境調整カードが出ている場合は、その候補を`shop_context`へ優先する。身体操作しか主提案でなくても、同じ選択中の不調と反応プロファイルに適合する環境調整からショップ文脈を作る。身体操作そのものの商品属性は参照しない。

楽天検索は`tool-*`の許可済みaction idだけを受け付け、取得商品にも役割別の適合フィルターをかける。

### スタンド系の保証

`screen_height`は次の両方を満たす商品だけを通す。

1. スマホ、タブレット、ノートPC、モニター、本など、見る対象の用途語がある。
2. スタンド、書見台、読書台、モニター台、机上台など、支える形状語がある。

これにより、収納トレーやマイクスタンドを画面高さケアへ混ぜない。胃腸の前かがみ専用文では`tool-work-height:screen_height`の上書き検索を使い、画面・読み物用スタンドへ限定する。

医療用品を除外する正規表現から裸の`固定`を外し、`固定帯 / 固定具`へ狭めた。これにより`クランプ固定`と説明された通常のスタンドを誤除外しない。

## 変更していないもの

- 予報点数とシグナル
- 天気ストレス計算
- 共通反応プロファイル
- 7つの方針とその身体反応の対応
- 出やすいサインの生成
- 食べる、ほぐすの基本構造
- DBスキーマと環境変数

## 固定した回帰条件

- 全7天気 × 9不調で、表示される身体操作の商品属性が無効である。
- 身体操作主提案の日も、ショップ文脈のaction idは`tool-*`である。
- 表示中の環境調整がある場合、ショップ文脈はその候補を優先する。
- 胃腸の前かがみケアは`screen_height`で検索する。
- タブレットスタンドは通し、収納トレーとマイクスタンドは弾く。
- `細い持ち手`、`片手の袋を二つに分ける`という旧文を表示ソースへ残さない。
