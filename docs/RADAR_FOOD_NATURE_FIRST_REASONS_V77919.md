# v7.79.19 食性中心の選定理由・食材優先表示

## 目的

食べるケアを一般的な栄養アプリへ寄せず、未病レーダーの中心である`天気の揺さぶり × 体質反応 × 余力 × 気血水 × 不調`から、その日に合いやすい食性を示す。

完成料理は実行例として必要だが、ユーザーが同じ料理を作れるとは限らない。そこで主役を料理名から食材へ移し、食材を別の料理・惣菜・外食へ置き換えられる表示にする。

## 表示契約

食事候補は次の順で表示する。

1. `取り入れたい食材`
2. `料理案`
3. `食養生`の理由
4. `栄養面`の補足

飲み物候補は次の順で表示する。

1. 飲み物名
2. `食養生`の理由
3. `成分・飲み方`の補足

食性の説明では`清熱 / 理気 / 化湿 / 生津 / 温中`をそのまま出さず、次の生活語へ翻訳する。

- 熱を冷ます
- お腹や体を温める
- 温める・冷ますの偏りが少ない
- 乾きをやわらげる
- 重さや水分の偏りをためにくくする
- 香りで張りつめた感じを動かす
- 消耗した日の食事を支える

## 食事データ

`mealCandidate`の完成料理辞書は、自然な料理案とtoday/tomorrowの用途分離を保つために維持する。

表示時は`MEAL_FOCUS_INGREDIENTS`の監修済みパターンだけで主要食材を抽出し、次の構造へ変換する。

```js
{
  label: "鶏肉とズッキーニのバジルトマトパスタ",
  focus_ingredients: ["鶏肉", "バジル", "トマト"],
  meal_example: "鶏肉とズッキーニのバジルトマトパスタ",
  reasons: [
    { label: "食養生", text: "..." },
    { label: "栄養面", text: "..." },
  ],
}
```

自由な単語分割は使わない。たとえば`小腹が空いたら`の`たら`を魚と誤認しないよう、魚の`たら`は料理名の先頭または明示的な区切り位置だけで認識する。

## 飲み物データ

飲み物の選定は既存の`DRINK_ITEMS`を正本にする。

- `nature`: 寒熱
- `flavors`: 五味
- `tags`: うるおす、熱を冷ます、重さをためにくくする、胃腸を支える等
- `goodFor / cautionFor`: 天気・不調との適合と注意
- `caffeine / caffeineLevel`: 栄養・時間帯側の補足

選定時には主・副天気、不調、体質サブラベル、today/tomorrowに加え、反応方向も使う。アクセル寄りでは`calm`を加点し、カフェインを小さく減点する。ブレーキ寄りでは胃腸を支える候補や覚醒方向を小さく加点する。

表示時は寒熱から食養生理由を作り、カフェイン・ポリフェノール・飲む時間・温度は二段目へ置く。

## 互換性

- `action_cards.items`は記録キーとの互換性のため完成料理名を維持する
- 新UIは`item_details.focus_ingredients`を第一表示にする
- `foodIngredientRules`の飲み物`item_details`を`enhanceFoodContext`で維持する
- 旧保存データに飲み物の構造化理由がない場合だけ、旧文字列を`食養生 / 成分・飲み方`へ互換変換する
- ショップへ単日の料理名・食材を渡さない。継続商品はv7.79.17のマクロ軸で選ぶ

## 変更していないもの

- 予報点数・天気ストレス
- 予報カードの出やすいサイン
- 共通反応プロファイルと7つの方針
- 暮らすケア・ほぐすケア
- ショップの継続ケア軸
- DB・環境変数

## 回帰確認

- 食事理由が`食養生 → 栄養面`
- 飲み物理由が`食養生 → 成分・飲み方`
- 高温日の麦茶に`熱を冷ます方向 / カフェインなし`が出る
- 食事の第一表示用に主要食材が一件以上取れる
- 今日と明日は別料理カタログ・別日付で同一候補へ固定しない
- 専門店前提の外国料理を通常候補へ戻さない
