# v7.79.11 暮らすケアの環境・身体二系統契約

## 目的

暮らすケアの役割を、次の二つへ絞る。

1. その日の天気ストレスへ直接触れる環境調整
2. 天気・体質・選択中の不調に合う身体の使い方

予定、休憩、止め時、家事の軽量化、ペース配分は行動療法の領域であり、天気ストレスと体質から出す暮らすケアには含めない。

## 環境調整

`ENVIRONMENT_EXPERIMENT_CANDIDATES`は次の6件だけを現行候補とする。

- `env-damp-window-choice`：外の湿気が強い日の換気と除湿を切り替える
- `env-heat-window-radiation`：日が当たる窓から入る熱を減らす
- `env-heat-humidity-mode`：暑さと湿気が重なる時に冷房・除湿へ切り替える
- `env-dry-airflow-line`：顔や首へ当たる乾いた風の線を外す
- `env-cold-airflow-line`：首や肩へ当たり続ける冷風の線を外す
- `env-cold-floor-contact`：床から足裏へ続く冷たさを減らす

環境候補は主または副の天気ストレスに一致する時だけ候補化する。`env-heat-humidity-mode`だけは`heat`と`damp`の両方を必須とする。

気圧自体は室内環境で変えられない。寒暖差も上昇・低下の物理方向を確定できない状態では、冷えや暑さの環境案へ勝手に投影しない。この二つだけの日は環境レーンを空にする。

## 身体の使い方

内部の正中張力OS、9基本動作、22件のaction idは維持する。

身体操作は`requireSymptomMatch = true`とし、選択中の不調に直接つながる候補がない時は身体レーンを空にする。めまい時の歩行・階段・深い拾い動作など、既存の安全除外も維持する。

ユーザー文は次の順で表示する。

1. 使う生活場面
2. 試す一手
3. 短い理由
4. ラクになった目安
5. しっくりこない時の戻し方

内部の専門語は画面へ直接出さない。姿勢の形を採点せず、本人が感じる軽さ、詰まり、踏ん張りの差を目安にする。

## 選定

- レーン内の候補点は天気、ケア方針、不調、体質軸、余力から計算する
- 身体と環境の最高点を比較し、高い方を主提案にする
- 最高点差が`LIFESTYLE_LANE_NEAR_TIE_DELTA = 0.75`以内の時だけ日付ローテーションする
- 各レーン内も最高点差`0.75`以内の場面・具体策だけをローテーションする
- `LIFESTYLE_MIN_DISPLAY_SCORE = 2.5`未満の候補は表示しない
- 主提案1件、別案1件、合計最大2件
- 件数を満たすための三件目、基礎ケア、別レーンの低適合候補は追加しない
- 両レーンが空なら`primary_action=null / steps=[] / no_suggestion=true`

身体操作と環境調整を毎日交互に出す処理は置かない。ほぼ同点の時だけ主役を回す。

## UIとショップ

- 身体操作の体感欄：`ラクになった目安`
- 環境調整の体感欄：`合っている目安`
- 提案なし：暮らすで無理に埋めず、食べる・ほぐすへ案内
- 商品名・検索語：対策ケアカードへ出さない
- ショップ：現行6件の環境action idと身体action idを、許可済み辞書で商品候補へ変換
- 旧`env-stop-line / env-breathing-room / foundation-*`は現行ショップ辞書から削除

## 変更しないもの

- 体調ゆらぎ度
- 天気ストレス
- 体質親和性
- 余力補正
- 出やすいサイン
- 食べるケア
- ほぐすケア
- 予報保存形式
- DB / SQL / environment variables
