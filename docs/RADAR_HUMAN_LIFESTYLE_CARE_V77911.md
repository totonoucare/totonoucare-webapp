# v7.79.11 暮らすケアの有用性・生活者言語

## 修正した違和感

v7.79.10までの環境・基礎ケアには、アプリが知らない暮らしを前提にした候補があった。

- 濡れた物が作業場所の近くにある
- 食後に運動を始めようとしている
- その場にタオル、着替え、飲み物がある
- 一般的な水分・休憩・着替えを、まだ本人がしていない

これらは天気・体質・不調からは判断できない。実際の暮らしに合わない助言を件数合わせで表示すると、対策ケア全体への信頼を下げる。

## 有用性ゲート

新しい候補は、次をすべて満たす時だけ表示する。

1. アプリが持つ天気または不調の情報と接点がある
2. 特殊な部屋、持ち物、職業、生活習慣を仮定しない
3. 本人が既に当然している可能性が高い一般論を主提案にしない
4. 余裕が落ちた後でも、追加の準備を増やしにくい
5. その場で何をするかが一読で分かる
6. 姿勢の正解ではなく、本人がラクさの差を確かめられる

両レーンに適合候補がなければ、`primary_action=null`として暮らす提案を休む。空欄を埋めるフォールバックは置かない。

## 現行候補

### 身体の使い方

内部の正中張力OSと22件のaction idは維持する。画面文は次の順で短く表示する。

1. 具体的な生活場面
2. その場で試す一手
3. なぜ少しラクになりやすいか
4. ラクになった目安
5. しっくりこない時の戻し方

専門語、姿勢採点、断定的な効果表現は画面へ出さない。

### 段取りをラクに

現行の環境側候補は次の2件だけ。

- `env-stop-line`：始める前に「ここまでで終わり」を決める
- `env-breathing-room`：外せない予定の前後どちらかを10分空ける

どちらも天気ストレスのある日に限って候補化し、特定の部屋や道具を前提にしない。

## 文章契約

ユーザー表示では次を避ける。

- `〇〇ではなく〇〇`
- `〜するためです`
- `〜できています`
- 専門家が採点するような姿勢の正解
- ビジネス文書のような抽象語
- 本人の行動を見たかのような決めつけ

文体は短い`です・ます`を基本にしつつ、実行文と戻し方は`〜してみる / 〜でOK / 〜しよう`まで崩してよい。

## 表示数

- 主提案：最大1件
- 別案：最大1件
- 合計：最大2件
- 三件目の補充：なし
- `foundation`：新規選定なし

## 変更しないもの

- 体調ゆらぎ度
- 天気ストレス
- 体質親和性
- 余力補正
- 出やすいサイン
- 食べるケア
- ほぐすケア
- 予報保存形式
- DB / SQL / environment variables
