# v7.79.3 水分環境の状態と変化方向

## 修正の目的

これまでのV2は、絶対湿度を使って湿気・乾燥を評価していましたが、変化負荷が絶対環境負荷を上回る場合に、絶対湿度の変化方向から表示側を決めることがありました。

そのため、一日中湿潤域にいる大阪の夏日でも、絶対湿度が低下中というだけで`乾燥`が選ばれ、痰湿・気虚傾向ではなく乾燥側の体質親和性が使われる場合がありました。

## 新しい情報分離

| 情報 | フィールド | 役割 |
|---|---|---|
| 水分環境の状態 | `moisture_state` | 湿気側・乾燥側のどちらにいるか、体質親和性 |
| 水分量の変化方向 | `moisture_direction` | 上昇・低下・上下変動、ピーク時間帯 |

`moisture_state`は対象日の絶対湿度から次のように判定します。

| 値 | 判定 |
|---|---|
| `damp` | 14g/m³超を含み、8g/m³未満を含まない |
| `dry` | 8g/m³未満を含み、14g/m³超を含まない |
| `neutral` | 全点が8〜14g/m³ |
| `mixed` | 8g/m³未満と14g/m³超の両方を含む |

## 個別予報での優先順位

1. `moisture_state = damp`なら、変化方向にかかわらず湿気側の親和性を使う
2. `moisture_state = dry`なら、変化方向にかかわらず乾燥側の親和性を使う
3. `neutral / mixed`では、中間帯から離れる変化か、中間帯へ戻る変化かを見て湿気・乾燥へ投影する
4. `moisture_state`を持たない旧スナップショットは、従来の変化判定を維持する

これにより、

- 湿潤域の中で絶対湿度が下がる: `湿気・低下中`
- 乾燥域の中で絶対湿度が上がる: `乾燥・上昇中`

という、状態と物理変化を矛盾なく保持できます。

## 変更していないもの

- 体調ゆらぎ度のスコア重み
- 気圧・気温ロジック
- 余力補正
- 体質チェック
- 湿度カードの2表示（湿気・乾燥）
- DBスキーマ
- 環境変数

## 回帰確認

- 終日14g/m³超かつ低下中でも`damp`
- 終日8g/m³未満かつ上昇中でも`dry`
- 状態情報がない旧データは従来の離脱・回復判定
- 気圧、気温、体質差、公開デモの既存テスト
